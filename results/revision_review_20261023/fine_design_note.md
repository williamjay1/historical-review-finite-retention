# Fine-cadence archive condition

The finer SMD stream is an actual previously computed stream, not interpolated coarse scores and not duplicated high records. All 28 devices have existing width-ten PCA and ridge score arrays at stride one. The same model, train-fitted normalization, channel error scales and calibration cutoff generated the paired stride-ten stream. The new adapter reads these arrays without fitting anything. All 56 paired coarse score arrays match the original frozen score arrays bit for bit; at their shared timestamps, all fine arrays also match the paired coarse arrays bit for bit. Every stored window-last value was independently compared with the original raw test value at the completed window edge.

The archive-specific provenance tape is held fixed: the original coarse review arrivals are mapped to the first fine decision at or after the same source sample. The older fine feedback replay had a changed request tape; that tape is not used here. Thus differences in archive evidence arise from the emission schedule and corresponding actual records, rather than extra simulated feedback. Public event annotations enter only after atoms, support, headers and baseline parent identities have been constructed.

The original source contains 327 contiguous binary incidents. The interpretation-label audit supplies exact-boundary contributing-dimension annotations for 322 of those incidents, giving 2,254 incident–dimension targets. These are distinct cohorts; the number 322 is not a correction of the total binary incident count. All 327 remain in model-output opportunity counts, while only the 322 exact matches supply annotated-channel queries. No dimensions are fabricated for the five unmatched incidents.

At stride ten, 249/327 incidents have a completed active decision; stride one gives 327/327. PCA active model-output hit incidents increase from 143 to 238 and ridge from 142 to 239. Within the exact annotation cohort, PCA affected-dimension evidence increases from 122 to 216 incidents and ridge from 135 to 224. Positive incident–dimension intervals increase from 749/2,254 to 1,101/2,254 for PCA and from 932/2,254 to 1,228/2,254 for ridge. The 371 empty annotation scopes per backbone become zero. An archive cannot repair the remaining incidents with no emitted affected-channel high.

Actual high-record counts grow from 24,415 to 238,339 for PCA and from 111,954 to 1,124,754 for ridge. Summed channel-specific high-support runs increase from 7,084 to 32,880 and from 12,492 to 68,024, respectively. This changes both evidence availability and the amount and structure of input to storage; it is not an arbitrary byte-cap reduction. Neither the source stream nor this stress condition establishes any actual field-device storage budget or analyst query distribution.

The source codec audit uses three existing reversible layouts (AoS, independent columns and bitmap plus values), creates 336 actual files and independently reopens every file. All records decode bit for bit. For these audit-specific, fully charged headers, the cheapest complete representation fits 64 KiB on 54/56 coarse histories and 36/56 fine histories; it fits 256 KiB on 55/56 coarse and 53/56 fine histories, and 1 MiB on all coarse and 55/56 fine histories. The definitive new common experiment uses its own additional completeness/usability framing, so its exact cost results supersede these adapter-readiness costs in the manuscript.

The particularly informative observed server is machine-3-4 ridge. Its actual high atoms grow from 60,483 to 605,210 and the complete bitmap-plus-values audit file from 304,973 to 2,743,030 B. Its annotation-positive pairs increase from 20 to 30 and active-decision opportunities from five to all eight binary incidents. The corresponding PCA stream has 2,374/23,884 atoms and 12,364/88,175 B complete files. The two model results reuse the same eight event identities.

The cached ESA finer-cadence products are not equivalent full-mission archive streams. Mission 1 contains 299,177 event-local windows with 54 schedule gaps; Mission 2 contains 8,356 with five gaps. Those windows were selected using event intervals and generated using a numerical PCA refit because original weights were not persisted. They remain a separately disclosed event-local cadence diagnostic. Treating them as continuous label-blind mission storage workloads would confound archive policy with label-selected omission; they are therefore excluded from the primary fine archive condition.

Executable interface: `review_fine_stream_20261023.to_driver_stream(entity, backbone)` supplies the same dictionaries and query construction as the common coarse archive driver. Main fine archive comparisons are written incrementally by `review_fine_experiments_20261023.py` with per-run source hashes and physical-file decoding assertions. These results remain software/task evidence, not human-time, fault-resolution or physical-safety effects.

## Definitive common-implementation results

The final 56-fit run finished in 145.55 s and created 672 budgeted files (six policies, two budgets per fit), with 1,344 family-level aggregate rows. Every file was reopened by the common decoder before query scoring. The final common-core, driver, adapter and runner files were unchanged throughout this run; these hashes are in `fine_static_completion.json`. The earlier exploratory hard-server pilot is explicitly marked superseded because it preceded the parent-group selection and equal-length method-header corrections. Only the full final outputs should supply manuscript numbers.

At 64 KiB, adaptive complete-if-fits with coverage-summary/fill certifies and retrieves 1,015/1,101 exact first records for PCA and 993/1,228 for ridge. Parent-change bitmap plus fill retrieves 893 and 887, respectively. The extra numeric service comes with 11/2,254 and 67/2,254 unknown presence answers for adaptive coverage, against zero for the complete support bitmap. At 256 KiB all PCA histories fit complete storage, giving 1,101/1,101 joint first records and all 2,254 complete query reports. Ridge adaptive coverage gives 1,146/1,228 joint first records versus 1,122 for bitmap/change/fill, but seven unknown presence answers versus zero. These are alternative service preferences; the evidence does not support declaring one universal best policy.

The current real anomaly task example is incident 2 on machine-3-4, ridge, annotated variable 10, at source samples 6,013–6,015. Three high records occur in this activity interval. At 64 KiB, the physical bitmap/change file occupies 65,528 B and certifies first time 6,013 but retains none of the three requested numeric records. The coverage-aware first/last/min/max file occupies 49,766 B, certifies the same first time and retrieves its exact float32 score 215.59866333007812, window-last value 1.0 and provenance version 6. It retains one of the three records and therefore correctly refuses a complete-detail report. The coverage/fill file spends 65,526 B but still does not recover the two missing records. This case is recorded in `fine_task_case.json`; it is not the older nominal-only notification vignette.
